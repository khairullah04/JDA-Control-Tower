**Top 3 risks**

1. **Typed work is lost.** Esc or Cancel discards the invoice form without asking (5); a finished Drive sync overwrites an open form (22); an expired session is suspected to force a cancel (13); refresh empties the editor (14); the Edit report screen clears half-typed entries each time it re-locks (30). Nothing anywhere keeps a draft.
2. **One click changes live data with no undo.** Bulk "Set status" pre-set to Paid (6); "Clear completed" and "Load sample…" (7); Edit report's "Sync from Drive" (8); the Editor Page's Remove buttons and Reset (9, 10); the block editor's Save publishing everything (11).
3. **I can't tell what was actually saved, or whether a figure is right.** A refused status still shows as Paid (4); a stale exchange rate is saved as a Bank Negara rate (3); there is no "saved" message for invoices or Edit report (12, 15); AI-read invoices look the same as checked ones and have no link to their source file (2, 23).

**What's done well**

- The invoice form shows Original → MYR → Tax → Taxed MYR as I type, and the payment month follows the invoice date until I set it myself (jda/web/js/ui/finance-ui.js:129-133, 159-169).
- Invoices and sanctioned amounts are never really deleted: Delete explains itself, "Show deleted" > Restore brings them back, and History shows who changed what (jda/web/js/ui/cji3.js:84; jda/web/js/finance/service.js:60-74; jda/web/js/ui/finance-ui.js:219-230).
- Import always shows a row-by-row preview with the reason for each rejected row and skips invoices already entered; a Drive invoice with gaps arrives as "Incomplete" with what is missing rather than being dropped (jda/web/js/ui/finance-io.js:36-55; jda/web/js/services/sync.js:39-46).

**Score:** 5/10. The invoice register is careful about figures and history, but daily entry is slowed by the missing file attach and "add another", and across both sites typed work is easy to lose and several single clicks change live data with no way back.
