Firestore rules for the portal's report documents
=================================================

The JDA Control Tower's report pages read each JDA's report document straight from Firestore, with
the person's sign-in. Writing is closed: every save goes through the JDA server
(POST /api/portal/save), which checks the sign-in and writes with its service-account key.

JDA 1 and 2 (project test-invoice-c38a4)
-------------------------------------------
Nothing to add by hand: firebase/firestore.rules already holds this block. Publish that file.

    match /jdaReports/{doc} {
      allow read: if onAccessList();
      allow write: if false;
    }

JDA 3 (its own project, jda3-9c0c5)
-----------------------------------
In that project's console (Firestore Database -> Rules), replace the report block with:

    match /report/{doc} {
      allow read: if true;
      allow write: if false;
    }

JDA 3's report stays readable by anyone who knows the project while its read rule is "if true":
the JDA Control Tower sign-in does not reach that project. To make it private too, the server must
read it with JDA3_GOOGLE_APPLICATION_CREDENTIALS and the rule become "allow read: if false". That is
listed under Known issues in OVERHAUL_CHECKLIST.md.

Two things must be in place BEFORE you publish it, or JDA 3 stops updating:
  1. The JDA server needs a service-account key for jda3-9c0c5
     (JDA3_GOOGLE_APPLICATION_CREDENTIALS in server/.env), or the editor cannot save JDA 3.
  2. The Excel -> Power Automate feed that writes report/current must write with a service account
     too. If it writes the way a browser does, the closed rule will refuse it.

Previous versions of each report are kept by the server in a `versions` subcollection of the
document (the newest 20). No rule opens that subcollection, so no browser can read it.
